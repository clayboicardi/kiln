## Discoveries (worth carrying forward)

1. **SQLDelight type-narrows queries with `IS NOT NULL` filters on nullable columns.** Example: `selectRecentlyPlayed: ... WHERE last_played_ms IS NOT NULL` generates a custom `SelectRecentlyPlayed` row class with `last_played_ms: Long` (non-null) instead of using the generic `Track` class with nullable types. Required separate `SelectRecentlyPlayed.toMediaItem()` mapper. Pattern to anticipate for any future type-narrowed queries.

2. **SQLDelight cannot parse FTS5 control commands inline.** `INSERT INTO track_search(track_search) VALUES('delete-all')` failed to compile because SQLDelight's parser requires column names to match table schema. Workaround: removed maintenance queries from `.sq` file; LocalLibrarySource issues these via raw `driver.execute(...)` when needed.

3. **`kotlinx.coroutines.flow.transform { rows -> rows.forEach { emit(...) } }` is the idiomatic "Flow<List<T>> → Flow<T>" bridge.** Alternatives (custom `flatten1d` helper, `flatMapConcat { it.asFlow() }`) have receiver-type-inference quirks or opt-in stability concerns. Use `transform` for this pattern.

4. **AudioFrame requires manual `equals`/`hashCode`.** ByteArray's default equals is reference-equality; custom impl using `contentEquals` matters for any test or queue-state diff that compares AudioFrames. Captured in `Decoder.kt`.

5. **Compose-MP libs aren't api-exposed by `:ui:*` modules via project deps.** The `:ui:components` + `:ui:theme` modules declare `bundles.compose-mp-common` as `implementation` (not `api`), so consuming app modules (`:app-android`, `:app-desktop`) must add the bundle directly to access Compose types in their source code.

6. **`:app-desktop` ALSO needs `compose.desktop.currentOs`.** Canonical Compose Desktop pattern: `compose.desktop.currentOs` provides platform-specific Skia + window toolkit jars. Combined with `bundles.compose-mp-common` for the foundation/material3/ui types.
