## Discoveries (worth carrying forward to the cumulative gotcha list)

10 new gotchas this session — all promoted to `CLAUDE.md` Build/Dep Gotchas section:

1. **Vendored *.dll requires explicit !-exception in .gitignore.** The repo's `.gitignore` line 32 (`*.dll`) was added for future native-build output (AAudio/WASAPI phase-2b). Vendored libraries under `:audio:playback/src/desktopMain/resources/native/**` need !-exceptions or git will silently exclude them, leading to JAR-without-native-lib at runtime. Verified via `git check-ignore -v`.

2. **Kotlin packages can't safely use `native` as a segment.** Java reserves `native` as a keyword for native methods; the JVM bytecode emits package paths as Java-style segments, so `com.foo.bar.native.X` can trip tooling. Use `nativeio` (or similar non-reserved name) — Kotlin source compiles either way, but tooling consistency wins.

3. **JNA Windows-canonical library name drops the "lib" prefix.** `Native.load("FLAC", LibFlacBinding::class.java)` looks for `FLAC.dll` on Windows, not `libFLAC.dll`. When vendoring Xiph's `libFLAC.dll`, extract the temp copy as `FLAC.dll` so JNA's name resolution finds it. Belt-and-suspenders: also `System.load(absolutePath)` before `Native.load` — the OS loader caches the lib regardless of name.

4. **JNA callbacks need strong references for the duration of native use.** `libFLAC` stores the callback function pointers (raw C-style), and if the JNI wrapper is garbage-collected mid-decode, the next callback invocation crashes the JVM with a JNI fault. Hold callbacks as fields on the owner of the decoder handle (`JvmFlacDecodedStream` does this for the three callbacks).

5. **libFLAC's STREAMINFO union starts at offset 16 in FLAC__StreamMetadata.** Header: type(4) + is_last(4) + length(4) = 12 bytes, then 4-byte padding because the union's largest natural alignment is 8 (uint64 total_samples in STREAMINFO). `metadataPtr.share(16)` is the correct way to point a JNA Structure at the union body.

6. **libFLAC delivers samples as FLAC__int32 regardless of bit depth.** Pack down to LE bytes per the source bit depth. For 24-bit: take the low 3 bytes (sign preserved via upper-byte mirroring because libFLAC sign-extends bit 23 into bits 24–31). For 16-bit: low 2 bytes. For 32-bit: all 4. Bulk-read via `Pointer.getIntArray(0, blocksize)` per channel before interleaving — ~10× faster than per-sample getInt at 4096 blocksizes.

7. **ffprobe + FLACs with embedded album art emits duplicate keys.** Without `-select_streams a:0`, ffprobe's default-format key=value output runs through both the audio stream AND the picture stream, and the picture-stream's bit-depth (often 8) silently overwrites the audio-stream's. Surfaced as a `bits_per_raw_sample` mismatch on a real-world FLAC; fix is to pin the stream selection.

8. **JUnit 4 @Test methods must return void/Unit.** `fun foo() = runBlocking { assertNotNull(x) }` breaks because `assertNotNull` returns `T` (the non-null value), and `runBlocking` returns the lambda result. Either explicitly return Unit (`Unit` as last statement), or use `assertTrue(x != null, ...)` (returns Unit), or use `assertEquals(expectedValue, x)`.

9. **Kotlin smart-cast doesn't propagate through complex sealed-type narrowing with side-effecting calls.** `val r = X(); if (r !is Either.Right) { log.w { ... }; return }; r.value` may fail to smart-cast even though it's logically valid, because the lambda in `log.w { ... }` defeats the cast tracking. Use `when (val r = X()) { is Either.Left -> { ...; return }; is Either.Right -> r.value }` — when-as-expression has cleaner smart-cast propagation.

10. **Kotlin's `internal` is module-scoped.** A class marked `internal` in `:audio:playback` is NOT accessible from `:app-desktop` even though both are in the same Gradle build. For DI graphs in separate modules consuming impl classes, either make the class public OR expose a public top-level factory function returning the public interface type (this codebase chose factories: `createJvmFlacDecoder()`, `createJavaSoundPlayer(...)`).

## Trap-detection prompts (plan §9) — retrospective

- **"Architecture as Performance Art" check.** Did I over-engineer the libFLAC bridge? **No.** The split — NativeLibraryLoader / LibFlacLoader / LibFlacBinding (JNA interface) / FlacCallbacks (3 typed callbacks) / FlacStreamMetadataStreamInfo (JNA Structure) / FlacMetadata (parser helper) / FlacFrameReader (hot-path interleaver) / JvmFlacDecodedStream / JvmFlacDecoderImpl — mirrors libFLAC's C-side concept boundaries. Each file has one job; consumers (the DI graph, the public factories) see only the `Decoder` + `DecodedStream` interfaces from commonMain. Bus-Factor-of-One satisfied.

- **"Curator's Trap" check.** Did I assume Clay's library characteristics? **Mildly.** The smoke test scans D:\tiddl alphabetically and takes the first 10 FLACs — which all happened to be 16/44 stereo (the 2 Chainz albums at the top of the alphabet). 24-bit / 24/192 / multichannel matrix coverage came from the bundled fixtures (sine_440_stereo_16_44.flac + sine_440_stereo_24_96.flac) instead of from Clay's library directly. Phase 2a can broaden the smoke to actively pick format-diverse files. Documented in the smoke test header.

- **"Bus-Factor-of-One" check.** Could Clay read what was written in 6 months without me? **Yes.** Each native file leads with a multi-paragraph header explaining what's there + why + cross-references to FLAC's `stream_decoder.h` for binding sources. Critical gotchas (24-bit packing, callback-lifetime, union offset 16) are inline-documented with reasoning. The factory pattern's "why public" is explained in the docstring.

- **"Mastering Engineer's Apartment" check.** Are the new modules clinical instruments arranged with care? **Yes.** The `nativeio` package contains 7 files in a tight cluster, each named for the C-side concept it mirrors. Tests are 1:1 with impl files in most cases. The DI graph reads top-to-bottom: storage → source → scanner → audio dispatcher → decoder → player.

- **"Engine-Swap-Shaped Boundary" check.** Could Phase 2b swap Java Sound for WASAPI behind the same interface? **Yes.** `PlatformPlayer` is the interface (commonMain). JavaSoundPlayerImpl is just one impl. Swap-in WasapiPlayerImpl by changing the DesktopAppGraph's `player()` provider; `Decoder` + `DecodedStream` + the consumer surface stays identical. Vetting Item 13 invariant intact.
